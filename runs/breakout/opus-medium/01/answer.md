## Design

**Strategy: move the paddle toward the column where the ball will reach row 8.**

The target is T = f(x + dx·(8−y)), where (x, y) is the ball's cell and dx is its horizontal direction. The function f folds the line back at the walls the way this file does it: f(u)=u for 0..9, f(u)=19−u for u ≥ 10, and f(u)=−u−1 for u < 0. The fold repeats the wall cell because the ball's x is clamped there for one step.

- **Descending ball:** the formula is exact.
- **Ascending ball:** bricks never sit below row 3, so the ball must turn at row 4 or higher. That makes the formula an underestimate, so the paddle leads the ball without overshooting.
- **Paddle bounce:** at row 8 the formula gives the ball's own column, which is correct.
- Because the formula does not depend on the vertical direction, the trail's row is not needed.

**Getting the direction linearly.** The quantity x_ball − x_trail is linear in the one-hot inputs. It is +1 when the ball moves right and −1 when it moves left. It is 0 only when the ball is clamped at a wall, and then it is about to move away from that wall. So two linear "gates" (weight 100) select exactly one direction:

- right-gate = 100·(x − tx + [x=0] − 1)
- left-gate = 100·(tx − x + [x=9] − 1)

Each gate is 0 when its direction applies and −100 or less otherwise. Under a gate, T is a pure function of the ball's cell, so it is linear in the ball one-hot input.

**Layer 1 (4 units):**
- h0 = tanh(4(T_R − P − ½) + gateR), meaning "move right" (right-moving case).
- h1 = tanh(4(P − T_R − ½) + gateR), meaning "move left" (right-moving case).
- h2 and h3 are the same pair using T_L and the left gate.

Here P is the paddle column. The ball weights are 4·(±T) plus the gate's x-terms, the trail weights are ∓100·tx, and the paddle weights are ∓4c.

**Layer 2:**
- R = tanh(3(h0 + h2 + 1))
- L = tanh(3(h1 + h3 + 1))

**Outputs:** right = 10·R and left = 10·L. No-op is 0, so it is chosen when the paddle is already at the target. The other no-op actions are set to −10.
