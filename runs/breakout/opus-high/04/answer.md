## Design

**Strategy.** The ball moves one cell per step, and so does the paddle. A catch happens on the step where the ball goes from row 8 to row 9. At that moment the paddle (after its move) must be in the two-cell set {ball_x, ball_x + dx}. In mirror coordinates (walls act as mirrors at −0.5 and 9.5), the centre of that set is a half-integer target **c**. The rule is:

- move right if c − p ≥ 1.5,
- move left if c − p ≤ −1.5,
- otherwise do nothing, because the paddle is already in the catch set.

The paddle therefore stops at the near end of the set. A sticky repeat of the move that brought it there only carries it to the other end, so the catch still happens.

**How c is chosen.**
- **Ball moving down, or a flat move** (brick or ceiling bounce, or the reset state): c is the exact landing point, `reflect(bx + dx·(8.5 − by))`.
- **Ball moving up:** c is the landing point if the ball bounces off the nearest brick row it could still hit. That is row 3 while the ball is below the bricks, then the next row up, then the ceiling. This value stays fixed during a straight climb. If the ball actually goes higher, the extra climbing time more than covers the larger distance.

For a known direction (dy, dx), c depends only on the ball's cell. So it can be stored as a 100-entry table in the ball channel. The direction itself comes from comparing the ball and trail cells, and the wall-clamp cases are handled explicitly.

**Breaking loops.** When the ball is on row 8 and the paddle is already in the catch set, the policy picks no-op or "move to the other end of the set" about 50/50. Both choices catch the ball, but one sends it straight on and the other reflects it sideways. This randomness stops the ball from settling into a fixed cycle that never reaches the remaining bricks.

**Hidden units.**

Layer 1 (gain 8; every threshold has a margin of 0.5):
- **Units 0–7:** `[c − p > 1]` and `[c − p < −1]` for four target tables: down/flat moving right (D+), down/flat moving left (D−), up moving right (U+) and up moving left (U−).
- **Units 8–11:** the row-8 tie units `[c − p > 0]` and `[c − p < 0]` for each horizontal direction. All other ball rows get −50 so these units stay off.
- **Unit 12 (Mr):** ball moving right, computed as `bx + [bx=0] − tx > 0.5`. This also handles balls stuck against a wall.
- **Unit 13 (Up):** ball moving up, computed as `ty − by > 0.5`.

Layer 2: units 0–11 each compute an AND of three inputs: one comparator, Mr or not-Mr, and Up or not-Up.

Output logits:
- **Right and left:** −10 when nothing fires, +10 when a comparator fires, 0 when only a tie unit fires.
- **No-op:** 0.
- **Up, down and fire:** −10.
