## Design

**Strategy.** The ball's horizontal motion is a pure billiard: it only reverses at the side walls, where it stays in the wall column for two steps. Bricks, the top wall and the paddle never change it, except for a reversal paddle hit. So for a ball at row `y`, column `x`, I can read off exactly where it will be `n = 8 − y` steps ahead:

- moving right: `T_R = fold(x + n)`, with `fold(u) = u` if `u ≤ 9`, else `19 − u`
- moving left: `T_L = x − n` if that is `≥ 0`, else `n − x − 1`

The paddle moves toward that column and stops there.

- **Descending ball:** `T` is the exact landing column on row 8, so the paddle arrives early and waits.
- **Ascending ball:** `T` is a point on the ball's future path that it cannot reach sooner than `n` steps, so heading there never costs time and cuts the corner at wall bounces.
- **Ball on row 8:** `n = 0`, so the target is the ball's own column. That gives the "paddle directly under the ball" hit, which keeps the ball's horizontal direction. It also means the ambiguous direction right after a paddle hit never matters.

Keeping the horizontal direction makes the ball sweep the whole grid like a billiard, so it should not settle into a brick-free back-and-forth loop.

**Horizontal direction** comes from ball column minus trail column, `D`. If they are equal, the ball has just been clamped at a wall (or the episode has just started) and is moving away from that wall. This gives two linear gates that are exactly 0 when true and ≤ −1 otherwise:

- right: `D − 1 + [x = 0]`
- left: `−D − 1 + [x = 9]`

**Layer 1 (4 units used, K = 10, M = 200).** Each unit is `tanh(K·(±(T − p) − 0.5) + M·gate)`, where `p` is the paddle column. `T` and the gate are lookup weights on the one-hot ball cell; the trail contributes `∓M·column` and the paddle `∓K·column`.

| Unit | Fires (+1) when |
|---|---|
| 0 | ball moving right and `T_R > p` |
| 1 | ball moving right and `p > T_R` |
| 2 | ball moving left and `T_L > p` |
| 3 | ball moving left and `p > T_L` |

**Layer 2.** Unit 0 is "go right" = unit 0 OR unit 2. Unit 1 is "go left" = unit 1 OR unit 3.

**Output.** Right logit = 20 × (go right), left logit = 20 × (go left), all no-op actions 0. The policy is effectively deterministic; when the paddle is on target both move logits are −20 and it stays.

Nothing was run, so this is unverified. By hand-tracing, a single sticky-action slip looks survivable in the cases I checked, because nearly every trip includes a wall bounce that gives the paddle slack.
